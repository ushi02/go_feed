项目架构 · 本地优先

Go Feed Reader

一个多人使用的 RSS 阅读器：每个网站只抓取一次文章，每位用户独立管理订阅、文件夹、已读和收藏。

系统由什么组成？

浏览器阅读与管理订阅
→
React + Vite列表、文件夹、OPML
→
Go API账号、查询与阅读状态
→
MySQL所有正式数据
外部网站RSS、Atom、JSON Feed
→
Go Worker定时抓取、去重、重试
→
MySQL文章与抓取进度

添加订阅后会发生什么？

1 · 找到 Feed

输入博客首页或 Feed 地址。若首页提供多个订阅入口，用户可以选择。

2 · 尽快抓取

新源立即进入待抓取状态。Worker 认领任务，并在安全限制内访问源站。

3 · 独立阅读

文章只存一份；每人的订阅、已读水位和收藏状态分别保存。

为什么要有已读水位？

订阅已有源时，只有最近 20 篇默认未读。批量标已读只推进该订阅的文章 ID 水位，不会为每篇文章插入一条用户状态。单篇手动改动保存在稀疏状态表中。

将来怎样上云？

托管方案：S3 + CloudFront 提供前端，ECS Fargate 运行 Go API 和 Worker，RDS for MySQL 保存数据。个人低成本方案：一台 Lightsail 或 EC2 运行 Compose，前端仍可放在 S3 + CloudFront。当前登录限流保存在 API 进程内；扩容到多个 API 实例时需要共享限流方案。
